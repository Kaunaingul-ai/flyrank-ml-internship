Content Decline Prioritization with Machine Learning

A public-safe decision-support study for ranking content pages that may deserve editorial review or refresh.

Abstract

This study investigates whether public-safe page-level search and content signals can be used to identify and rank content pages that are more likely to be declining. The analysis uses an anonymized dataset of 30,000 content pages and compares a rule-based baseline with a Random Forest classifier on the same held-out validation set. The baseline achieved a Precision@50 of 0.60, while the Random Forest achieved 0.88, with 44 of its top 50 recommendations corresponding to observed declining pages. The model also achieved an Average Precision of 0.733 and ROC AUC of 0.723. The results support the model as a decision-support tool for prioritizing editorial review, while avoiding causal claims or claims about Google's ranking algorithm.

1. Introduction and Problem Statement

Editorial teams often have more content pages than they can manually inspect. The practical question is therefore not simply whether a page is declining, but which pages should be reviewed first when editorial time is limited.

This project follows the Refresh / Content Opportunity Scoring lane. The research question is: Can public-safe page-level search and content signals be used to rank content pages that are more likely to be declining?

The intended output is a ranked review queue. It is not an automated instruction to modify content. Human editors remain responsible for deciding whether a page should be refreshed, rewritten, consolidated, monitored, or left unchanged.

2. Data

The analysis uses the anonymized public-safe starter dataset provided through the FlyRank Machine Learning internship repository. The dataset contains 30,000 page-level observations and 44 columns.

The features used in the modeling workflow are:

  • 90-day impressions
  • Click-through rate (CTR)
  • Average search position
  • Content age in days
  • Days since last update
  • Word count

The observed outcome is whether trend_direction equals "down". This field is used only as the label for evaluation and training and is excluded from the model input features.

The full gated FlyRank warehouse release was not available during this analysis. Therefore, this project does not use private client names, URLs, domains, private search queries, or warehouse-only tables.

3. Methodology

The task is framed as a binary prediction and ranking problem. A Random Forest classifier estimates the probability that a page belongs to the observed declining class. These probabilities are then used to rank pages for editorial review.

The dataset was split into 80% training data and 20% held-out validation data using stratification. This produced 24,000 training rows and 6,000 validation rows, with a decline rate of approximately 0.542 in both sets.

Median imputation was used for missing numeric values. A fixed random seed was used for reproducibility.

Baseline

The Week-4 baseline assigns rule-based priority using content staleness and low CTR relative to search position, with impressions used only as a small tie-breaker.

Evaluation

The primary metric is Precision@50 because the operational decision is which small set of pages should be reviewed first.

Secondary metrics include Average Precision and ROC AUC.

5. Limitations and Honest Framing

The results should be interpreted as validation performance within the available anonymized starter dataset. Because the dataset does not provide a clear client grouping variable or explicit time window suitable for grouped or time-aware validation, a stratified random hold-out split was used.

The model identifies statistical associations with the observed decline label. It does not establish that any feature causes decline.

The model also does not explain, reproduce, or predict Google's search ranking algorithm.

Important contextual variables such as seasonality, query intent, page purpose, business priority, and editorial quality may not be represented in the public-safe feature set.

The model should therefore be treated as a decision-support system, not an automatic content decision-maker.

6. Ranked Recommendations

Model scores are converted into a ranked editorial review queue. Higher-scoring pages are prioritized for human inspection.

The top 50 pages are marked REVIEW_FIRST. Editors can then inspect those pages and decide whether the most appropriate action is refresh, rewrite, consolidation, monitoring, or no change.

In the held-out validation sample, 44 of the top 50 model-ranked pages were observed to be declining.

The public paper does not expose private URLs, domains, search queries, or client identities.

7. Reproducibility

The analysis was developed in reproducible notebooks stored in the project repository.

The capstone notebook contains the full workflow, including data loading, feature definition, leakage checks, train-validation splitting, baseline construction, model training, evaluation, ranked recommendations, and error analysis.

Key analysis notebook: work/notebooks/capstone.ipynb

The model uses a fixed random seed so that the main validation results can be reproduced consistently.

8. Conclusion

The study demonstrates that a machine-learning ranking model can improve the prioritization of potentially declining content pages compared with a simple rule-based baseline.

The Random Forest improved Precision@50 from 0.60 to 0.88 on the same held-out validation set. This means the model concentrated more observed declining pages near the top of the editorial review queue.

The practical value of the system is therefore not automatic content modification, but better allocation of limited editorial attention.
